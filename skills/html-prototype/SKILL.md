# html-prototype — 单文件 HTML 可玩原型

## 定位

**快速验证两件事**：核心循环是否成立、玩法手感是否符合预期。

所以：**不要考虑 UI 好不好看，不要考虑手感打磨，不要考虑画面表现。** 越快产出越有价值 —— 一个 5 分钟就能玩起来的粗稿，胜过 30 分钟的精致 demo。视觉上白底 + 纯色色块 + emoji 就够。

这个原型的价值在于「早」。在核心循环还没验证前写 500 行详细设计文档，是在为一个可能不成立的设计做精细化。

---

## 硬性要求

1. 输出**一个完整 HTML 文件**：`<!DOCTYPE html>` 到 `</html>`。
2. **单文件、零外部资源**：CSS/JS 全内联；不引用 CDN、图片 URL、字体链接；图标用 emoji 或 CSS 画。
3. **整页代码 ≤ 300 行**（HTML + CSS + JS 合计）。超了说明你在做不必要的事。
4. 在浏览器直接打开即可玩，鼠标 + 触屏都能操作。
5. 顶部注释写明：`<!-- 原型：<玩法名> —— 验证目标：<一句话> -->`
6. 中文文案。

---

## 必须有的骨架

其余一律省略：

- **开始界面**：标题 + 一行操作说明 + 开始按钮
- **核心循环可交互**：有最基础的得分 / 进度 / 失败反馈（数字变化即可，不需要特效）
- **一局结算**：本局分数 + 最佳分数 + 重开按钮；最佳分数存内存变量即可
- **单局时长 30 秒 ~ 3 分钟**，必须能完整玩通一局

---

## 明确禁止

这些会拖慢生成，且对验证毫无价值：

- 粒子、动画、缓动、屏幕抖动、音效、飘分特效
- 精致布局、卡片、阴影、渐变、暗色主题、响应式 / 多端打磨
- 存档、设置项、难度选项、多步教程
- 派子 agent、联网搜索、读取与本步骤无关的文件
- 更新任何配置文档，或写原型 HTML 之外的文件

---

## 平台约束（压缩为 3 条）

1. **竖屏**：内容放进居中容器，最大宽约 480px；**横屏**：铺满视口。游戏区域不随窗口变形。
2. 手机触控与鼠标都要可用（大按钮 / 点击即响应即可）。
3. 伪 3D 概念用色块与透视布局表达即可，不做真 3D。

---

## 交付

写入 `specs/<project>/02-prototype/prototype.html`（多次迭代用 `prototype-v<N>.html`）。

**聊天回复只写一句完成说明**（玩法名 + 验证目标），不要在回复里重复代码。

开始前不要做多余的探索：直接读核心循环描述，然后写文件。

---

## 自检清单

写完后确认：

- [ ] 双击能在浏览器打开，直接可玩
- [ ] 从开始到结算能完整玩通一局
- [ ] 核心循环在原型里**确实能跑通**（不是纸面上成立）
- [ ] 整页 ≤ 300 行
- [ ] 无任何外部资源引用
- [ ] 手机与鼠标都能操作
- [ ] 顶部注释写了玩法名与验证目标

---

## 原型的验证结论

原型玩完后，明确给出三条结论：

1. **核心循环是否成立** —— 成立 / 不成立 / 需要调整（说明调整点）
2. **手感与预期的偏差** —— 哪里比预期好、哪里比预期差
3. **是否值得进入详细设计** —— 结论 + 理由

不成立的循环，回到 `concept-interview` 修核心循环，不要在错误循环上继续往下设计。
