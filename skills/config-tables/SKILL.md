# config-tables — 属性与数值配置表

## 定位

把设计落到**可交付给程序的 CSV 表格**，并用一份说明文档讲清每张表怎么用。

配置表是给程序和策划的**接口契约**：表结构错了，后面所有数值工作都建立在错误的口径上。

---

## 工作方式

1. 通读「模块详细设计」，识别所有**需要外部配置**的实体与数值（角色/单位属性、关卡、掉落、成长曲线、商店价格、任务等）。
2. 决定拆几张表：**1 张到多张**，每张表覆盖一个内聚的模块或实体类型。**不要把所有东西塞进一张巨型表。**
3. 先写说明文档，再逐张写出 CSV 文件。

---

## CSV 表格设计规则

| 规则 | 说明 |
|---|---|
| **第一行为表头** | 列名用中文、简洁明确，如 `名称,生命值,攻击力,品质,解锁等级`；再加一列 `备注` 说明用途 |
| **每行一个条目** | 一个角色、一个关卡、一个商品……；第一列用唯一标识 |
| **枚举列** | 状态、类型、品质等取值有限的列：在说明文档中列出该列的**全部可选值集合**，表内只使用集合内的值（程序会渲染为下拉选择） |
| **数字列** | 填纯数字，不带单位、千分位或引号（程序会渲染为数字输入框） |
| **文本列** | 需要换算或公式的，写清公式（如 `=攻击力*1.2+10`）或直接给出计算结果 |
| **数值口径** | 与「模块详细设计」口径一致；设计未给出的数值，按合理基准给出并标注「建议值」 |

---

## 说明文档内容

```markdown
# 配置表说明

## 表格清单
| 文件 | 表名 | 覆盖模块 | 行数 | 关键列 |
|---|---|---|---|---|

## 每张表逐张说明
### <表名>
- **用途**：这张表给哪个模块/系统用，程序里怎么读它
- **列定义**：逐列说明 —— 列名 | 类型（文本/数字/枚举） | 含义 | 取值约束
  → **枚举列必须给出全部可选值集合**
- **与其他表的关联**：外键关系（如 `掉落表.物品ID` → `物品表.ID`）
- **示例行解读**：挑一行解释每个字段怎么填

## 数值口径
- 表中数值与详细设计的对应关系
- 哪些是「建议值」，需要后续数值分析确认
```

---

## 表拆分原则

按**内聚的模块或实体类型**拆，不要按「字段多少」拆：

| 该拆 | 不该拆 |
|---|---|
| 角色属性表 / 技能表 / 装备表 各自独立 | 一张 `all.csv` 塞 30 列 |
| 掉落表与物品表分离（物品可被多处引用） | 掉落物品名重复写在掉落表里 |
| 关卡表与关卡波次表分离 | 把波次塞进关卡表的 JSON 列 |
| 商店表与商品表分离 | 商品信息在商店表里重复维护 |

**外键要显式**：跨表引用的字段必须在说明文档里写清指向哪张表的哪一列。

---

## 约束

- 表内枚举列的值必须能和说明文档的可选值集合**一一对上**
- 数字列不带单位 / 千分位 / 引号
- 全程中文
- 直接输出文档与文件写入说明，**不要把 CSV 全文贴到聊天回复**

---

## 与其他技能的衔接

| 技能 | 关系 |
|---|---|
| `module-design` | 上游 —— 提供模块清单、实体定义、数值口径 |
| `numeric-balance` | **下游 / 互为迭代** —— 数值模型以本技能配置表为口径来源；配置表错则数值全错。若数值模型与配置表冲突，须显式指出并给修正建议 |

产物写入 `specs/<project>/05-data/`（`config-tables.md` + 各 `*.csv`）。

## 自检清单

- [ ] 每张表覆盖一个内聚的实体类型，没有巨型表
- [ ] 表头为中文 + 唯一标识列 + `备注` 列
- [ ] 每个枚举列在说明文档里列出了**全部**可选值，且表内值都在集合内
- [ ] 数字列是纯数字，无单位 / 千分位 / 引号
- [ ] 跨表外键关系已在说明文档写明
- [ ] 「建议值」已标注，供后续数值分析确认
- [ ] 数值与模块详细设计口径一致，差异已说明
