# game-design-workflow — 游戏设计工作流总控

## 定位

这是**总控技能**，不直接产出设计文档。它负责：

1. 判断当前处于哪个阶段、下一步该做什么
2. 检查上游产物是否齐备，决定能否推进
3. 把上游产物作为上下文交给对应阶段技能
4. 在关键节点做质量门禁，不合格就退回重做

各阶段的具体方法论在独立技能里，本技能只引用，不复述。

---

## 阶段流水线

```
① concept-interview  概念与立项
        │  产物：访谈记录、一页纸概念案
        ▼
② html-prototype     核心循环可玩原型
        │  产物：单文件 HTML 原型
        ▼
③ module-design      模块详细设计
        │  产物：模块详细设计文档
        ├──────────────┬──────────────┐
        ▼              ▼              ▼
④ numeric-balance  ⑤ ui-design   ⑥ config-tables
   数值经济模型      模块 UI 原型     CSV 配置表
        │              │              │
        └──────────────┴──────┬───────┘
                               ▼
                    ⑦ player-review  玩家视角评估
                               │
                               ▼
                    玩家总结报告 → 修订清单 → 回到 ③
```

## 阶段依赖表

| 阶段 | 技能 | 依赖上游 | 核心产物 |
|---|---|---|---|
| ① | `concept-interview` | — | 访谈记录、一页纸概念案 |
| ② | `html-prototype` | ① | 单文件 HTML 可玩原型 |
| ③ | `module-design` | ①② | 模块详细设计文档 |
| ④ | `numeric-balance` | ①③⑥ | 经济数值模型、养成曲线 |
| ⑤ | `ui-design` | ③ | 逐模块静态 HTML 原型 |
| ⑥ | `config-tables` | ③ | CSV 配置表 + 说明文档 |
| ⑦ | `player-review` | ①②④ | 各画像评估 + 总结报告 |

**关键约束：**

- ② 必须早于 ③。原型的存在意义是验证核心循环，先出设计再补原型会掩盖问题。
- ⑥ 必须在 ④ 之前或与之迭代。数值模型以配置表为口径来源，配置表错则数值全错。
- ⑦ 在最后。评估要基于完整设计资料，提前评估只会得到片面的意见。
- ⑦ 的结论**回流到 ③**（修订详细设计）与 ④⑥（调整数值配置），形成闭环。

---

## 阶段推进判断

进入本技能时，先判断当前处在哪个阶段：

**判据（按序检查）：**

1. 没有任何设计文档 → 阶段 ①
2. 有概念案，没有可玩原型 → 阶段 ②
3. 有原型，没有模块详细设计 → 阶段 ③
4. 有详细设计，缺以下任一项 → 分别补 ④⑤⑥
   - 数值模型缺失或与设计口径冲突 → ④
   - 模块 UI 原型缺失 → ⑤
   - 配置表缺失 → ⑥
5. 全部齐备 → 阶段 ⑦
6. 已有玩家总结报告 → 按修订清单回改，回到 ③ 或 ④

**不要跳阶段。** 每个阶段的存在都对应一类「事后补救成本远高于事前验证」的失败模式：

| 跳过 | 后果 |
|---|---|
| 跳过 ① 直接写设计 | 大量设计决策建立在未确认的假设上 |
| 跳过 ② 直接详设 | 核心循环不成立时，详设越详细浪费越大 |
| 跳过 ⑥ 直接算数值 | 数值模型失去口径来源，全靠拍脑袋 |
| 跳过 ⑦ 直接进开发 | 没人从玩家视角挑毛病 |

## 质量门禁

每个阶段交接前必须检查，不通过就退回本阶段重做，**不要带着问题往下走**。

### ① → ② 门禁

- [ ] 一句话概念能说清「类型 + 题材 + 核心差异点」
- [ ] 四项固定信息已确认：开发平台、画面形式（2D/3D）、游戏类型、屏幕适配（横竖屏 + 比例）
- [ ] 核心循环已用文字描述清楚（玩家重复做什么 → 得到什么反馈 → 投入什么 → 挑战什么）
- [ ] 访谈中没有被 AI 代答的痕迹

### ② → ③ 门禁

- [ ] HTML 原型能在浏览器直接打开玩
- [ ] 能完整玩通一局，有开始与结算
- [ ] 核心循环在原型里**确实成立**（不是纸面上成立）
- [ ] 手感与预期基本符合，或已明确记录偏差

### ③ → ④⑤⑥ 门禁

- [ ] 文档开头的名词表已建立，全文术语一致
- [ ] 每个模块都有：定位、游戏逻辑、交互、表现（含音频音效）、模块关系、边界异常
- [ ] 逻辑闭环：无「定义了没人用」「用了没定义」的机制
- [ ] 一个没参与讨论的开发者只读文档能照着实现

### ④⑤⑥ → ⑦ 门禁

- [ ] 数值模型的资源口径与配置表一致（冲突已指出并修正）
- [ ] 每个 UI 原型只做展示、不含玩法逻辑
- [ ] 配置表枚举值与说明文档的可选值集合一一对应

### ⑦ → 回流 门禁

- [ ] 总结报告的修订清单具体到模块名 / 表名 / 数值项，不是「再优化一下」这类空话
- [ ] 少数画像的关键意见未被归并丢失

## 通用铁律

以下规则在所有阶段生效，**优先级高于任何阶段技能里的要求**。

### 1. 不替用户作答

访谈类环节中，AI 只提问和引导，**决策权在用户**。

- 禁止虚构或补全用户的回答
- 禁止出现「开发者答：」「用户答：」「你可能想说：」「我猜你的意思是：」等任何形式的用户侧文本
- 举例说明只能写在 AI 自己的分析里，并明确标注「以下是我的推测，请你确认」
- 用户回答过短或跑题，只能追问，不得替他补充

### 2. 数字必须能算出来

任何数值结论都要给出计算过程，不接受「大概」「感觉」「一般来说」。

- 表格里的乘除关系要能对上
- 关键数字给出算式或脚本计算路径
- 假设要显式列出，并说明「假设不成立时」的敏感点

### 3. 口径冲突必须显式指出

上下游数值/定义冲突时，**不要静默选一个**，要指出冲突、给出取舍建议与理由。

### 4. 不虚构外部事实

竞品、市场数据、行业惯例必须来自实际检索，并注明出处链接。检索不到就标注「未经核实」，**绝不编造数据**。

### 5. 一次只问一个问题

访谈环节严格一次一问，问题后附 2~3 个示例选项降低回答难度。问完一轮先总结确认再推进。

### 6. 产物写文件，不贴聊天框

设计文档、原型 HTML、配置表 CSV 都写入文件。聊天回复只给一句话完成说明，不要把大段代码或表格贴进对话。

### 7. 全程中文

术语非必要不使用英文；确需英文的（通行行业术语）给出中文解释。

## 产物落盘约定

统一放在项目的 `specs/<project-name>/` 下，与对话上下文分离：

```
specs/<project-name>/
├── 01-concept/
│   ├── interview-notes.md      访谈记录
│   └── one-pager.md            一页纸概念案
├── 02-prototype/
│   └── prototype.html          可玩原型（版本化）
├── 03-design/
│   ├── module-design.md        模块详细设计
│   └── numeric/
│       ├── economy-model.md    经济数值模型
│       └── progression.md      养成曲线
├── 04-ui/
│   └── <模块名>-v<N>.html      逐模块 UI 原型
├── 05-data/
│   ├── config-tables.md        配置表说明
│   └── *.csv                   配置表
└── 06-review/
    ├── <画像名>.md             各画像评估
    └── summary.md              玩家总结报告
```

**版本化规则**：同名产物多次生成时用 `名称-v<N>.<ext>` 递增，最新版本即当前版本，历史版本保留以便回溯对比。

## 常见任务的分发

| 用户说 | 走哪 |
|---|---|
| 「我想做一款 XX 游戏」 | 从 ① 开始，完整走流程 |
| 「帮我把概念案写出来」 | ① 的 one-pager 环节 |
| 「这游戏的核心循环怎么样」 | ① 核心循环 + ② 原型验证 |
| 「帮我写详细设计」 | ③ |
| 「数值怎么定」 | ⑥ → ④ |
| 「这个界面怎么排」 | ⑤ |
| 「配置表怎么设计」 | ⑥ |
| 「玩家会觉得怎么样」 | ⑦ |
| 「肉鸽怎么设计」 | 另用 `roguelike-design-architect` 技能补充 ③ 的内容 |
| 「给 Godot 项目换素材」 | 另用 `kenney-ui-art-replacer` 技能 |

用户只要求其中一段时，**直接跳到对应阶段**，但仍需检查该阶段的上游前提是否具备；不具备就先补最关键的那一项。
