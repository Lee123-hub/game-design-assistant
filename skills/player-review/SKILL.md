# player-review — 玩家视角评估与总结

## 定位

设计文档写完不等于设计成立。这一步换一副面孔：**扮演真实玩家**，用他们的视角把设计挑一遍毛病。

评估的价值不在「说得好听」，而在**发现设计者自己的盲区**。

---

## 第一部分：单人画像评估

扮演游戏中的一名**真实玩家**，完全以该画像的视角、习惯和偏好来看待当前设计。

> **你不是策划，不是顾问 —— 你是一个会掏钱、会卸载游戏的玩家。**

完整模板见 `references/persona-eval-template.md`，要点：

### 输出结构

```markdown
# 玩家评估：<画像名>

## 第一印象（30 秒测试）
- 只看概念和原型第一眼：我会不会点进去？为什么？

## 我会怎么玩
- 预期的一次典型游玩 session（什么时候玩、玩多久、玩什么）

## 亮点（真心话）
- 2~3 个让我想继续玩的设计，说明为什么打动我

## 劝退点（真心话）
- 2~4 个让我想关掉/卸载的设计，说明具体场景
  （"当我在……的时候，我因为……会退出"）

## 付费意愿（若为免费+内购）
- 我愿意为什么付钱？什么会让我觉得被逼氪？

## 打分
| 维度 | 评分(1-10) | 一句话理由 |
|---|---|---|
| 玩法趣味 | | |
| 上手门槛 | | |
| 长期动力 | | |
| （付费公平性，若适用） | | |

## 一句话总结
> 留下 or 卸载，为什么。
```

### 约束

- 全程**第一人称**、口语化，符合画像的说话方式（核心玩家会用术语，休闲玩家不会）
- 意见要**具体到设计细节**，不要空泛的「挺好的 / 还需优化」
- 直接输出文档本身

---

## 建议的画像配置

多画像并行是本技能的核心价值 —— 单一视角看不到分歧。建议至少覆盖：

| 画像维度 | 取值示例 |
|---|---|
| 硬核度 | 核心玩家 / 休闲玩家 / 新手 |
| 设备 | 移动 / PC / 主机 |
| 付费倾向 | 鲸鱼 / 月卡 / 零氪 / 买断党 |
| 动机 | 竞技 / 剧情 / 收集 / 建造 / 社交 |
| 耐心 | 愿意啃说明书 / 只看前三秒 |

画像之间**意见相反是正常的**（如核心玩家要深度 vs 休闲玩家要轻量）—— 分歧恰恰是最有价值的信息，不要在单人评估阶段强行调和。

---

## 第二部分：横向归并总结

汇总全部画像评估，形成玩家总结报告，作为概念与设计的最终校验。完整模板见 `references/summary-report-template.md`。

### 工作方式

1. 通读每一位画像的评估报告。
2. **横向归并**：不同画像共同提出的意见优先级最高；只有特定画像在意的意见标注适用人群。

### 输出结构

```markdown
# 玩家总结报告

## 评估概览
| 画像 | 一句话结论 | 打分（玩法/上手/长线/付费） |
|---|---|---|
（每个画像一行）

## 共识：必须修复
全部或多数画像都点名的劝退点/问题，按严重度排序；
每条注明是哪些画像提出的、对应哪个设计模块。

## 共识：值得保留
多数画像认可的亮点，说明为什么有效。

## 分歧与取舍建议
画像之间意见相反的地方：列出双方理由，给出制作人视角的取舍建议。

## 修订清单
- 对**详细设计**的具体修订建议（模块名 + 改什么）
- 对**数值/配置**的具体修订建议（哪张表、哪类数值怎么调）
- 对**概念定位**的建议（如适用）
```

### 约束

- 归并时**不要丢失少数画像的关键意见**，放进「分歧」或按人群标注
- 建议必须**具体可执行**，不要「再优化一下体验」这类空话
- 全程中文，直接输出文档本身

---

## 闭环：结论必须回流

总结报告的价值在于驱动修改。报告产出后，修订清单要回到上游：

| 修订对象 | 回流到 |
|---|---|
| 详细设计的模块问题 | `module-design` |
| 数值与配置问题 | `numeric-balance` / `config-tables` |
| 概念定位问题 | `concept-interview` |

**不要产出完报告就结束。** 没有被执行的修订清单等于没做。

产物写入 `specs/<project>/06-review/`（`<画像名>.md` + `summary.md`）。

---

## 自检清单

单人评估：
- [ ] 全程第一人称，口语化符合画像
- [ ] 劝退点具体到场景（"当我在……的时候"）
- [ ] 打分每个维度都有一句话理由
- [ ] 没有空泛评价

总结报告：
- [ ] 概览表覆盖全部画像
- [ ] 共识问题标注了提出者与对应模块
- [ ] 少数画像意见未被丢失
- [ ] 分歧给出了取舍建议而非罗列
- [ ] 修订清单具体到模块名 / 表名 / 数值项
- [ ] 已回流到上游技能
