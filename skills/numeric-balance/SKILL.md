# numeric-balance — 数值与平衡

## 定位

数值不是「填表」，而是**在预算约束下建立关系网**。好的数值策划不是知道「1 点攻击等于多少钱」，而是知道：

> 在这个玩法、这个阶段、这个玩家群里，系统允许一个对象获得多少价值，以及它必须为此付出什么代价。

**本技能分两步：先定性，后定量。** 跳过定性直接算数字，得到的只是一堆自洽但无意义的数。

---

## 第一步：数值口径访谈

先收集决定数值模型的定性输入。**这些答案是后续所有计算的唯一口径依据。**

### 访谈方式

1. **一次只问一个问题**，附 2~3 个示例选项降低回答难度。
2. 用户回答后，先总结确认，并说明**这个定性决策会如何影响数值模型**（产出节奏 / 付费深度 / 成长斜率）。
3. 回答过短（少于 20 字）则追问一次再继续。
4. 完成后输出结构化的**「定性输入小结」**（每项定性决策 + 对数值模型的口径影响），末尾单独一行输出 `[[FIELD_COMPLETE]]`。
5. 不超过 5 个问题；不替其他步骤执行任务（玩法、UI 等问题记录后让用户去对应阶段处理）。

### 必须确认的五项口径

| 项 | 要确认什么 |
|---|---|
| **目标体验与爽点节奏** | 前期宽松还是克制？正反馈（变强时刻）的期望频率？爽感优先还是策略深度优先？ |
| **会话时长与活跃分档** | 单次游玩时长目标？轻度 / 中度 / 重度如何划分（如轻度 30min、中度 1-2h、重度 3h+ 是否适用）？ |
| **成长速度预期** | 首日 / 首周玩家应达到什么节点（等级 / 战力 / 进度）？成长线预期铺多长？ |
| **商业化深度** | 买断 / 轻内购 / 重养成付费？付费是否直接影响数值强度，还是只影响外观与便利性？ |
| **数值参考基准** | 有无对标竞品或自定锚点（标准角色 DPS、单日收入预算等）？无则声明「无参考，按品类通识取值」 |

上游概念案与模块设计能推知的，先给出推断再请用户确认，不要重复问。

小结中**每项结论都要写明「对数值模型的口径影响」**，供后续计算直接引用。

## 第二步：经济数值模型

### 计算流程（先算后写）

1. **口径**：定性输入小结是所有数值的第一口径。与模块设计 / 配置表冲突时**以定性小结为准**，并在文档中指出冲突。
2. **核心数字必须脚本计算**：在工作区写零依赖脚本（Python 或 Node）计算产出/回收表、日/周净流量、通胀率等并打印结果表。**文档中的关键数字必须与脚本输出一致**，并给出「脚本路径 + 关键输出摘录」作为计算过程。
3. **按 SOP 自查**（见 `references/numeric-design-sop.md`）：锚点先行；产出/回收看 source/sink 净流量而非余额；随机掉落类产出给 P10/P50/P90 分位数而非只给均值。

### 输出结构

```markdown
# 经济系统数值模型

## 货币与资源体系
- 货币/资源分类（软币、硬币、材料、体力等），各自获取与消耗

## 产出模型
- 核心产出来源表（来源 / 单次产出 / 频次 / 日产出估算）
- 按玩家活跃度分档（轻度 30min / 中度 1-2h / 重度 3h+）

## 消耗与回收模型
- 主要消耗点表（系统 / 消耗品 / 单次消耗 / 频次）
- 产出/回收平衡分析：各周期（日/周）的通胀率估算

## 关键数值假设
- 模型依赖的关键假设，以及"假设不成立时"的敏感点

## 待验证问题
- 3~5 个需要原型或测试验证的数值问题
```

## 第三步：养成与成长曲线

### 计算流程（先算后写）

1. **口径**：定性输入小结是成长速度预期（首日/首周节点、成长线长度）的第一口径。与经济模型冲突时以定性小结为准并指出冲突。
2. **核心数字必须脚本计算**：写零依赖脚本计算成长曲线表、逐级**边际收益** `Marginal = Y(x+1) − Y(x)`、**增速** `Y(x+1)/Y(x) − 1`、资源缺口等并打印结果。文档关键数字与脚本输出一致，给出脚本路径 + 输出摘录。
3. **按 SOP 自查**：曲线重点看**边际收益是否跳变**而非绝对值；战力对标用 TTK 框架（`TTK ≈ Effective HP / Effective DPS`）；付费/免费进度差给出收敛机制。

### 输出结构

```markdown
# 养成与成长曲线

## 养成维度
- 角色/账号可成长维度（等级、装备、技能、其他），各自作用

## 成长曲线
- 每个维度的成长曲线表（阶段 / 累计投入 / 能力值 / 边际收益）
- 前 1 小时体验设计：每 10 分钟的"变强时刻"节奏

## 战力验证
- 对标内容难度曲线（如果概念支持战斗/挑战）：玩家战力 vs 内容难度，如何保持"略强于内容"
- 数值膨胀控制手段

## 付费/时长换算（若商业模式为免费+内购）
- 付费玩家与免费玩家的进度差与收敛手段

## 待验证问题
- 3~5 个需要测试验证的问题
```

**与经济模型保持资源口径一致**，不要引入未定义的货币 / 材料。

## 核心公式速查

完整推导与案例见 `references/numeric-design-sop.md`。

| 用途 | 公式 |
|---|---|
| 战斗时长 | `TTK ≈ Effective HP / Effective DPS` |
| 有效 DPS | `理论 DPS × Hit Rate × Uptime × Resource Factor × Buff Coverage` |
| Boss 反推 | `Boss HP = 期望遭遇时长 × 队伍有效 DPS`（**先定时长预算再填 HP**） |
| 经济恒等式 | `Ending = Beginning + Sources − Sinks + Transfers` |
| 净流量 | `Net Flow = Sources − Sinks`（**看流量不看余额**） |
| 边际收益 | `Marginal = Y(x+1) − Y(x)` |
| 增速 | `Growth = Y(x+1)/Y(x) − 1` |
| 技能价值 | `Adjusted = Raw × Reliability × Availability × Condition Factor` |
| 装备战力 | `Power = Base + Passive + Trigger + Synergy Premium − Opportunity Cost` |
| 卡牌期望 | `EV = Σ(p_i × payoff_i) − Cost`，偏离度 `= Actual / Baseline − 1` |
| 属性价值 | `V = w_hp·HP + w_atk·ATK + w_def·DEF + …` |

## 十条反模式自查

1. 以「50% 胜率」作为唯一平衡标准（忽略玩家分层、使用率、克制关系）
2. 只看面板不看获取成本（高 DPS 可能伴随低生存 / 低 uptime / 高风险）
3. 只看均值不看分布（尾部让大量玩家体验极差）
4. 只做静态表格不跑动态模拟（单级没问题，连续 30 级可能爆炸）
5. 只改一个参数不看乘法链（+10% 攻击经暴击/增伤/套装放大后远大于 10%）
6. 用堆 HP 替代难度设计（战斗只是变慢，不是变深）
7. 经济只看余额不看 source/sink（余额稳定 ≠ 无通胀风险）
8. 把玩家反馈当真理（反馈是问题线索，不是统计估计）
9. 把数据当真理（数据告诉你结果，不一定告诉你体验原因）
10. 上线后没有回归（一个补丁解决 A，可能制造 B/C/D）

**另有八类边界场景必测**：最优构筑、最差构筑、极限暴击、极限减 CD、低资源、高资源、新手、顶级玩家。
经济系统补充：极端囤货/卖货、套利、多账号高效农场。

> **合理数值不是平均场景合理，而是边界场景不崩坏。**

## 敏感性分析

每个关键参数至少测 `-10% / -5% / 0 / +5% / +10%`，看 `ΔOutput / ΔParameter`。

- 敏感度高的参数，设置更严格的改动权限（乘法链上的暴击倍率 ≠ 普通 base ATK 的调参节奏）
- 二阶检查：`ΔY/ΔX` 在区间内变化很快 = 非线性放大，最容易 live meta 爆炸
