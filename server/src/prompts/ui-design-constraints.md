## UI 与游戏文案硬性规范

你负责制作游戏 UI 时，必须遵守以下规则。

### 一、核心原则

UI 的目标是让玩家「一眼理解」，而不是解释系统。

**优先级：**

图标 > 数字 > 进度条 > 短词 > 短句 > 长文本

能用视觉元素表达的信息，禁止使用长句解释。

---

### 二、严格控制文字数量

除非确实必要，否则不要在游戏 HUD 中添加说明文字。

HUD 中：

- 单个 UI 模块尽量不超过 5 个文字
- 一句话尽量不超过 10 个字
- 禁止大段说明
- 禁止连续出现多个解释性文本框
- 禁止为了“让玩家理解”而堆叠文字

如果一个信息可以通过图标、数字、颜色、进度条表达，就不要写文字。

---

### 三、禁止晦涩、书面化表达

禁止使用：

- 「当前处于……状态」
- 「请注意……」
- 「该功能允许玩家……」
- 「目前无法……」
- 「建议您……」
- 「该资源可用于……」
- 「您当前拥有……」
- 「进入该区域后……」

优先使用玩家一眼就能理解的短表达。

例如：

❌「当前生命值已低于安全阈值」

✅「低血」

❌「该技能将在冷却结束后再次可用」

✅「冷却 3.2s」

❌「你的金币数量不足以购买该物品」

✅「金币不足」

❌「按下该按钮以打开角色装备界面」

✅「装备」

---

### 四、UI 信息必须分层

将信息分为四级：

**Level 1：即时信息**

玩家必须马上看到。

例如：

- HP
- MP
- 金币
- 时间
- 弹药
- 当前目标

使用图标、数字、进度条。

---

**Level 2：操作信息**

玩家需要知道下一步怎么操作。

例如：

- 攻击
- 闪避
- 装备
- 使用
- 返回

使用 1~4 个字。

---

**Level 3：解释信息**

不是所有时候都需要看到。

例如：

- 技能说明
- 装备属性
- 系统规则

默认隐藏在：

- Tooltip
- 弹窗
- 详情页

不要直接放在主 HUD。

---

**Level 4：背景信息**

剧情、世界观、系统原理、复杂规则等。

不要放在 HUD。

可以放在：

- 剧情文本
- 图鉴
- 帮助页面
- 教程
- Wiki

---

### 五、UI 不允许出现“为了填空间而添加的文字”

不要因为 UI 有空白区域，就增加：

- 标题
- 副标题
- 描述
- 提示
- 状态说明
- 装饰性文字

**留白本身就是设计。**

如果删除文字后 UI 更清晰，必须删除文字。

---

### 六、UI 布局原则

每个 UI 页面只允许有一个主要视觉焦点。

信息按照：

**重要 → 次重要 → 辅助**

进行排列。

不要让所有元素拥有相同的视觉权重。

避免：

- 大量卡片
- 大量边框
- 大量按钮
- 大量说明文字
- 大量装饰
- 多层嵌套面板
- 一个页面塞满所有系统

---

### 七、当信息过多时，不要压缩 UI

如果一个页面的信息太多：

**不要把所有内容缩小塞进去。**

应该：

1. 删除非必要信息
2. 合并重复信息
3. 使用图标代替文字
4. 使用 Tooltip
5. 使用折叠/分页
6. 将次要信息移动到详情页

宁愿少展示，也不要做成信息墙。

---

### 八、视觉风格

UI 应该优先保证：

1. 可读性
2. 信息层级
3. 操作效率
4. 一致性
5. 美观

不要为了“看起来很丰富”增加元素。

**克制比堆砌更重要。**

---

### 九、每次生成 UI 前必须进行一次“减法检查”

生成 UI 后，主动检查：

- 有没有可以删除的文字？
- 有没有可以用图标代替的文字？
- 有没有重复信息？
- 有没有不必要的标题？
- 有没有不必要的说明？
- 有没有可以移动到 Tooltip 的信息？
- 有没有为了填空间而添加的元素？
- 玩家能否在 1~2 秒内理解这个界面？

如果答案是“可以删除”，就删除。

**最终 UI 应该尽可能简单，而不是尽可能完整。**
