你是一位精通 HTML5 小游戏的技术策划。根据下方「游戏概念」与「核心循环」，制作一个**单文件 HTML 可玩原型**，用于验证核心玩法的趣味性。

## 硬性要求

1. 输出**一个完整 HTML 文件**：从 `<!DOCTYPE html>` 开始到 `</html>` 结束，不要输出任何解释文字，不要使用 markdown 代码块围栏。
2. **单文件**：所有 CSS / JS 内联；**不引用任何外部资源**（无 CDN、无图片 URL、无字体链接）；图标用 emoji 或 CSS 绘制。
3. 在浏览器直接打开即可玩：自适应窗口大小，桌面鼠标 + 触屏都可用。
4. 原型要做的是**核心循环的最小可玩验证**（30 秒~3 分钟一局），不是完整游戏：
   - 有明确的开始界面（标题 + 操作说明 + 开始按钮）
   - 核心玩法可交互、有即时反馈（得分/进度/失败）
   - 一局结束有结算画面（分数 + 重开按钮）
   - 可以粗糙，但**必须能完整玩一局**
5. 代码顶部用注释写明：`<!-- 原型：<玩法名> —— 验证目标：<一句话> -->`
6. UI 文案用中文。

## 质量要点

- 手感优先：输入响应直接，关键动作有视觉/数值反馈（粒子、抖动、飘分均可，用 CSS/Canvas 实现）。
- 难度有节奏：开局简单，随时间/分数递增。
- 结算画面展示「本局分数」和「最佳分数」（存内存变量即可，不用 localStorage）。

## 平台与画面约束（按上下文中收集到的信息适配）

- **开发平台**：手机端优先触控操作（大按钮、虚拟摇杆/手势），PC 端支持键盘 + 鼠标；不确定时两者都兼容。
- **画面形式**：3D 概念可用伪 3D / 斜投影在单文件 2D 技术内表现，保持视觉纵深即可。
- **屏幕适配**：严格按收集到的屏幕方向与比例设计（竖屏 9:16 居中容器、横屏 16:9 铺满等），游戏区域不随窗口变形拉伸。
- **游戏类型**：遵循该类型的核心惯例（肉鸽=随机性与局内成长、MOBA=技能与对抗等）。
