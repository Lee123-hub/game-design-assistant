# 游戏数值设计 SOP（精简版）

> 抽象自《游戏数值设计合理性 SOP：12款游戏案例拆解与通用方法论》，仅保留核心原则与可执行 SOP；案例调研与引用已剔除。
> 全文六个关键词：**目标、锚点、预算、分布、反馈、迭代**，其中核心是「预算」。

---

## 一、核心原则

### 1.1 数值合理性的定义：五层同时满足

| 层 | 要求 |
|---|---|
| 数学合理 | 公式、单位、边界、比例关系无矛盾 |
| 设计合理 | 数字支持玩法目标，而不是玩法被数字支配 |
| 体验合理 | 节奏、反馈、成长、风险回报符合目标人群 |
| 系统合理 | 单点调整不引发连锁崩坏；战斗/养成/经济可共同闭环 |
| 运营合理 | 上线后可观测、可调参、可回滚 |

> **数值合理 ≠ 所有单位数值接近。需要接近的，是"设计意图所要求的关系"。**

数值系统是一张关系网，不是各自的填表。每个关键数值必须回答：
1. 它依赖谁？ 2. 它影响谁？ 3. 它改变了什么玩家行为？ 4. 它被哪些系统放大/削弱？

### 1.2 四层模型（统一设计语言）

```
Intent（我要让玩家做什么）
  → Mechanism（靠什么机制实现：资源限制/CD/稀缺/克制/随机）
    → Numbers（数字怎样支撑机制：HP/ATK/cost/reward/probability/time）
      → Measurement（怎么证明有效：pick rate/win rate/TTK/留存/构筑多样性）
        → 回到 Intent 再校准
```

### 1.3 预算思想（最重要）

好的数值策划不是知道"1 点攻击等于多少钱"，而是知道：
> **在这个玩法、这个阶段、这个玩家群里，系统允许一个对象获得多少价值，以及它必须为此付出什么代价。**

- 战斗平衡 = 输出价值与成本的关系
- 养成平衡 = 当前成长速度与未来目标的关系
- 经济平衡 = 生成、消耗、转移和稀缺性的关系
- 卡牌平衡 = 费用、收益、条件、机会成本和环境交互的关系
- 随机平衡 = 期望、方差、尾部和玩家心理的关系
- 竞技平衡 = 不同玩家层级下的策略优势与反制关系
- 长期运营 = 被版本不断扰动的动态系统的稳定控制问题

### 1.4 十类常见错误（反模式自查）

1. 以"50% 胜率"作为唯一平衡标准（忽略玩家分层、使用率、克制关系）
2. 只看面板，不看获取成本（高 DPS 可能伴随低生存/低 uptime/高风险）
3. 只看均值，不看分布（尾部让大量玩家体验极差）
4. 只做静态表格，不跑动态模拟（单级没问题，连续 30 级可能爆炸）
5. 只改一个参数，不看乘法链（+10% 攻击经暴击/增伤/套装放大后远大于 10%）
6. 用堆 HP 替代难度设计（战斗只是变慢，不是变深）
7. 经济只看余额，不看 source/sink（余额稳定 ≠ 无通胀风险）
8. 把玩家反馈当真理（反馈是问题线索，不是统计估计）
9. 把数据当真理（数据告诉你结果，不一定告诉你体验原因）
10. 上线后没有回归（一个补丁解决 A，可能制造 B/C/D）

## 二、主流程（一页纸）

```
[1] 定义目标 → [2] 明确目标玩家/场景 → [3] 选择 baseline/anchor
→ [4] 建立预算（power/resource/time） → [5] 建立公式与关系网络
→ [6] 静态校验 → [7] 动态模拟（TTK/经济/曲线） → [8] 敏感性分析
→ [9] 极端场景 / Monte Carlo → [10] 原型试玩 → [11] 人感+数据双轨评估
→ [12] 版本前记录 baseline → [13] 灰度/小范围上线
→ [14] 观察 KPI/分布/异常/反馈 → [15] 保留/微调/回滚/重构
→ [16] 版本回归 + Change Log → [17] 更新 baseline
```

## 三、SOP 细则

### SOP-00 数值设计任务单

任何数值改动先填写，**没有问题定义，不进入调参**：

| 字段 | 内容 |
|---|---|
| 问题定义 | 当前哪里不合理？ |
| 目标体验 | 希望玩家有什么感受/行为？ |
| 目标群体 | 全体/新手/中期/高端/鲸鱼/竞技 |
| 受影响系统 | 战斗/养成/经济/掉落/商业化/匹配 |
| 关键指标 | 哪几个指标能证明问题被解决？ |
| 禁止副作用 | 哪些指标不能显著恶化？ |
| 改动范围 | 哪些参数允许改，哪些不允许？ |
| 验收窗口 | 立刻/一周/一版本/一赛季 |

### SOP-01 体验目标翻译成指标

每个设计目标 **至少对应 1 个行为指标 + 1 个结果指标**。示例：
- "新手升级快" → 前 30 分钟累计成长幅度、每 5 分钟正反馈次数、第 N 级资源缺口
- "Boss 有挑战但不恶心" → 平均 TTK、一次尝试成功率、学习后成功率增幅、机制失败占比 vs 数值压制占比

### SOP-02 寻找锚点（Anchor）

每个系统至少 1–3 个标准单位，**先把所有系统挂到共同锚点上，不要各系统单独成世界**：
- 战斗：标准角色 DPS / 标准怪物 HP / 标准技能 CD / 标准战斗时长
- 养成：玩家 1 天收入 / 每级经验预算 / 标准装备成本 / 标准成长幅度
- 经济：1 小时资源收入 / 标准资源包价值 / 常规装备材料成本 / 基础消费金额

### SOP-03 建立数值预算（核心）

- **属性**：`V = w_hp·HP + w_atk·ATK + w_def·DEF + …`（w_i 是相对价值权重；重点不是权重绝对正确，而是让团队有可争论、可校准的共同语言）
- **技能**：`Skill Value = 直接伤害 + 控制 + 机动 + 防御 + 协同`，再修正 `Adjusted = Raw × Reliability × Availability × Condition Factor`
- **装备**：`Power = Base Stat + Passive + Trigger + Synergy Premium − Opportunity Cost`
- **卡牌/道具**：`Expected Value = Σ(p_i × payoff_i) − Cost`，再做 power curve `Baseline = f(Cost)`，看偏离 `Curve Deviation = Actual / Baseline − 1`

### SOP-04 先静态校验，再动态校验

- 静态：越级值、比例断层、负值/溢出、上下限、单位一致、百分比 vs 百分点
- 动态：TTK、DPS、每分钟资源流量、每小时产出、成长斜率、资源缺口、奖励频率、失败率

> **静态合理 ≠ 动态合理。**

### SOP-05 增长曲线

三类：线性 `Y=aX+b`（早期/低复杂度）；指数 `Y=a·b^X`（长线养成，易前期快后期爆）；分段（生命周期本身分段，多数产品适用）。

**必做检查**：每级边际 `Marginal = Y(x+1) − Y(x)` 与增速 `Growth = Y(x+1)/Y(x) − 1`。
很多"不合理成长"不是绝对值太大，而是**边际收益突然跳变**。

### SOP-06 战斗统一用 TTK 框架

- `TTK ≈ Effective HP / Effective DPS`
- `Effective DPS = 理论 DPS × Hit Rate × Uptime × Resource Factor × Buff Coverage`（考虑暴击/miss/走位/CD/资源/增益覆盖/切目标）
- Boss 反推：`Boss HP = 期望遭遇时长 × 队伍有效 DPS`——先定时长预算，再填 HP，不要反过来
- 难度不要只靠堆 HP（见反模式 6）

### SOP-07 经济用 Source/Sink 流量模型

四张表：**Sources（产出）/ Sinks（消耗）/ Inventory（持有）/ Market（转移）**。

- 恒等式：`Ending = Beginning + Sources − Sinks + Transfers`
- 净流量：`Net Flow = Sources − Sinks`

长期健康不要求 `Net Flow = 0`，但要求：资产增长率在设计区间、消耗能力与新增内容同步、市场不长期失去稀缺性、不存在无成本造币循环。
> **看流量，不是余额。**

### SOP-08 敏感性分析

每个关键参数至少测 `-10% / -5% / 0 / +5% / +10%`，看 `ΔOutput / ΔParameter`。
- 敏感度高的参数，设置更严格的改动权限（如乘法链上的暴击倍率 ≠ 普通 base ATK 的调参节奏）
- 二阶检查：`ΔY/ΔX` 在区间内变化很快 = 非线性放大，最容易 live meta 爆炸

### SOP-09 极端/边界场景测试

至少 8 类：最优构筑、最差构筑、极限暴击、极限减 CD、低资源、高资源、新手、顶级玩家。
- 竞技补充：双方最优打法、counter matchup、多人协同、极端地图
- 经济补充：极端囤货/卖货、套利、多账号高效农场

> **合理数值不是平均场景合理，而是边界场景不崩坏。**

### SOP-10 Monte Carlo / 情景模拟

掉率、暴击、随机奖励、抽卡等系统单次计算无意义，模拟 N 次看分布：
P50（中位体验）、P10/P90（尾部）、P95/P99（极端运气）、方差、达标平均局数。

随机系统的核心问题不是"平均奖励多少"，而是：
> **多少玩家会在什么时候感到自己倒霉？**

需同时控制**期望、方差、尾部概率**。

### SOP-11 原型三层验证（趋势验证，非精确值验证）

- L1 纸面模型：结构是否合理
- L2 Excel/Python 仿真：曲线、预算、敏感度、极端情况
- L3 可玩原型：数字转成操作后是否真的合理

**L1/L2 都过，才值得投入大量美术和程序。**

### SOP-12 Playtest 双轨记录

|  | 数据异常 | 数据正常 |
|---|---|---|
| 玩家觉得有问题 | 优先级最高 | 查机制/可理解性 |
| 玩家觉得没问题 | 查隐藏尾部 | 基本通过 |

数据回答"发生了什么"，反馈回答"为什么"。

### SOP-13 上线前副作用清单

列出 `Primary → Secondary → Tertiary → …` 影响链。
例：Buff 装备攻击 → 装备 DPS↑ → Boss TTK↓ → 其他装备使用率↓ → 特定流派统治环境 → 材料价格改变。
> **越是乘法链上的参数，越要做全链路影响分析。**

### SOP-14 上线后控制图（Control Chart）

每个关键指标定义 Target / Warning / Action / Emergency 四档阈值。示例（数字仅为示例，正式阈值必须由项目历史数据估计）：

| KPI | Target | Warning | Action | Emergency |
|---|---:|---:|---:|---:|
| 胜率 | 50% | 48–52% | 47–53% | <46% 或 >54% |
| 使用率 | 8% | 5–11% | 3–13% | <2% 或 >15% |
| 通关率 | 30% | 25–35% | 20–40% | <15% 或 >45% |

### SOP-15 版本回归

每次调参后至少回归 7 项：
1. 原目标是否达成；2. Top 10 关联对象是否异常；3. 低端用户体验是否改变；4. 高端是否找到新 exploit；5. 经济 source/sink 是否变化；6. 核心 TTK 是否漂移；7. 是否出现新最优解。

> **版本不是调完就结束，而是一次新的实验。**
